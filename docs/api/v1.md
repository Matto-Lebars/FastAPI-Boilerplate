# API Reference (v1)

This project provides a versioned API under the `/api/v1/` prefix.

---

## 🔐 Authentication & Login

Endpoints for user authentication and session management.

### Login
- **Endpoint**: `POST /api/v1/login`
- **Description**: Authenticate with username/email and password.
- **Payload**: `OAuth2PasswordRequestForm` (username, password).
- **Response**: `Token` (access_token, token_type). Sets a `refresh_token` in a HttpOnly cookie.

### Refresh Access Token
- **Endpoint**: `POST /api/v1/refresh`
- **Description**: Issue a new access token using the refresh token from the cookie.
- **Payload**: None (reads from cookie).
- **Response**: `Token` (access_token, token_type).

### Logout
- **Endpoint**: `POST /api/v1/logout`
- **Description**: Invalidate the current session by blacklisting the tokens and clearing the refresh cookie.
- **Requires Auth**: Yes (Bearer Token).

## 👤 User Management

Endpoints for managing user accounts.

### Create User
- **Endpoint**: `POST /api/v1/user`
- **Description**: Register a new user account.
- **Requires Auth**: No.
- **Payload**: `UserCreate` (email, username, password, etc.).

### List Users
- **Endpoint**: `GET /api/v1/users`
- **Description**: Fetch a paginated list of all non-deleted users.
- **Query Params**: `page` (default 1), `items_per_page` (default 10).
- **Response**: `PaginatedListResponse[UserRead]`.

### Read Current User
- **Endpoint**: `GET /api/v1/user/me`
- **Description**: Get details of the currently authenticated user.
- **Requires Auth**: Yes (Bearer Token).

### Update User
- **Endpoint**: `PATCH /api/v1/user/{username}`
- **Description**: Update details for the specified user.
- **Requires Auth**: Yes (Bearer Token, must be owner).
- **Payload**: `UserUpdate` (partial updates for email, username, name, etc.).

### Delete User (Soft)
- **Endpoint**: `DELETE /api/v1/user/{username}`
- **Description**: Mark a user account as deleted and blacklist the current token.
- **Requires Auth**: Yes (Bearer Token, must be owner).

## 🏥 Health Checks

Endpoints to monitor the application's status.

### Health
- **Endpoint**: `GET /api/v1/health`
- **Description**: Basic check to ensure the application is running. Returns the environment and current version.

### Readiness
- **Endpoint**: `GET /api/v1/ready`
- **Description**: Comprehensive check including database connectivity. Returns `503 Service Unavailable` if the database is unreachable.
